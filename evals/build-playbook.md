# build-playbook 評価シナリオ

> スキルの動作を確認するための評価シナリオです。**配布バンドルには含めません**（`src/` の外に置いているため、`scripts/build.py` の出力には入りません）。スキルを変更したら、少なくとも1〜3を実行して期待動作との差分を確認してください。

## 実行方法

各シナリオの `query` をスキルに与え、`expected_behavior` をすべて満たすかを目視で確認します。自動評価の仕組みは用意していません。

---

    "確認事項が多いため一括フォームをファイルで配布する",
    "根拠が得られない基準値を推測で埋めず ※要確認 として残す",

  ]

## スクリプトの動作確認

`scripts/extract_review_feedback.py` は以下を満たすこと（合成ファイルで確認できる）。

| 入力 | 期待 |
|---|---|
| Wordコメント付き .docx | コメント本文と対象箇所（`anchor_text`）が対応付けて取れる |
| 変更履歴付き .docx | 挿入・削除・**移動**（`w:moveFrom` / `w:moveTo`）を種別ごとに計上する |
| 複数段落にまたがるコメント | 段落境界で改行され、語が連結されない |
| `対応` 列に `OK` / `Ok` / `ok` | いずれも `approved` に正規化される |
| `対応` 列が空欄 | `unanswered` に計上される |
| `対応` 列に対応表外の値 | `unrecognized` に計上される（素通りしない） |
| `.xlsx`（共有文字列・空欄セルあり） | 列がずれずに読める |
| Shift_JIS / UTF-8 BOM / UTF-16 の CSV | いずれも文字化けせず読める |
| 破損した .docx | 日本語のエラーで終了する（トレースバックを出さない） |
| 非対応の拡張子 | 対応形式を示して終了する |

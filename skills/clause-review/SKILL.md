# clause-review：条項チェックと修正案づくり（UC1）

## review-contract との使い分け

| | clause-review（本スキル） | review-contract |
|---|---|---|
| 想定ユーザー | 事業部門の交渉担当者 | 法務担当者 |
| 判定基準 | 業種別プレイブック（trading/pharma/staffing） | 自社共通プレイブック（references/playbook.md） |
| 固有の成果物 | 交渉トーク・譲歩ライン | Wordコメント挿入の詳細ガイドライン準拠レビュー |
| 曖昧な依頼のデフォルト | ✕（使わない） | ◯（こちらに振る） |

立場・業種の指定がない曖昧なレビュー依頼を受けた場合は、本スキルではなく review-contract を使うこと。

## 前提
- `../_shared/clm_rules.md`（URL規約・list_taskルール）と `../_shared/industry_presets.md` を必ず読み込むこと。
- 業種（trading/pharma/staffing）が未指定なら契約書の内容から推定し、判定開始前にユーザーへ確認する。
- CLM MCP未接続または対象文書が見つからない場合は `../_shared/sample_contracts/` で続行し、「（サンプルデータで実演中）」と明示する。

## 手順

### Step 1. 対象契約書の特定
1. ユーザーが文書を指定していない場合：`get_me`→`list_task`（pageSize=100）で自分担当・未完了（`completedAt`なし）のレビュータスクを作成日降順で取得し、上位5件を表形式（クリック用URLは `https://clm.contracts-cloud.com/ws/documents/{taskSource.taskSourceId}?nav=task` 固定）で提示して選択してもらう。
2. `download_document` で契約書ファイル（Word/PDF）を取得する。

### Step 2. プレイブック照合と赤黄緑判定
1. `assets/playbook_{industry}.md` を読み込む。業種プリセットの重点条項を優先的にチェックする：
   - trading：INCOTERMS／所有権移転・危険負担／与信・支払（L/C）／下請法条項
   - pharma：知財帰属／マイルストーン・ロイヤリティ／秘密保持／GxP関連
   - staffing：派遣可能期間・抵触日／偽装請負リスク（指揮命令）／事前面接禁止／手数料・返戻金
2. 条項ごとに判定：🔴 プレイブック逸脱（要修正）／🟡 要注意（交渉余地・条件付き許容）／🟢 問題なし。
3. 判定表を出力：条項番号／条項名／判定／逸脱内容／プレイブック基準。

### Step 3. 修正案と交渉トーク
🔴🟡の各条項について以下をセットで生成する：
- **修正案**：現行文言→修正文言（レッドライン形式）
- **交渉トーク**：相手に修正を受け入れてもらうための説明ロジック（相手側メリット・業界慣行・代替案）
- **譲歩ライン**：プレイブック上の許容下限

### Step 4. 版差分（旧版がある場合のみ）
CLM上に旧版があれば取得し、変更条項のみを「前回版→今回版→影響」の形で要約する。全文比較の羅列はしない。

### Step 5. 成果物の書き戻し（要承認）
以下を提案し、**ユーザー承認後に**実行する：
1. Word標準コメント機能で修正案を挿入した .docx を生成（docxスキル併用）
2. `get_upload_url`＋`update_document_version` で新版としてCLMへアップロード
3. `post_task_comment` で判定サマリ（🔴n件・🟡n件・🟢n件＋要点3行）をタスクに投稿
4. レビュー完了なら `complete_task` を提案

## 出力フォーマット
1. 判定サマリ（1行：🔴2 / 🟡3 / 🟢8 など）
2. 判定表（Markdown表・タスクリンク付き）
3. 修正案＋交渉トーク（🔴→🟡の順）
4. 次のアクション提案（legal-handoff / finance-impact への接続を案内）

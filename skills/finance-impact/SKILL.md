# finance-impact：会計・税務インパクトの先読み（UC3）

## 前提
- `../_shared/clm_rules.md` と `../_shared/industry_presets.md` を必ず読み込むこと。
- **このスキルは判断材料の整理に徹する**。会計・税務処理の最終判断は経理・税理士・監査法人に委ねる旨をシート末尾に必ず明記する。
- CLM未接続時はサンプル契約書で続行（明示）。

## 手順

### Step 1. 契約データの取得
1. `download_document` で契約書本文、`get_document_property_values` で契約金額・期間・相手方等の構造化プロパティを取得する。

### Step 2. 会計・税務論点のスキャン
業種プリセットの観点で、**該当条項を引用しながら**論点を抽出する：
- trading：本人/代理判定（グロス/ネット計上）に効く条項＝在庫リスク・価格決定権・与信リスクの所在／為替条項／支払サイト／与信保全（担保・保証）
- pharma：マイルストーン収益の計上時点／R&D費との区分／ロイヤリティ計上／消費税区分／移転価格（関連者間の場合）
- staffing：成功報酬の計上時点／返戻金の引当／立替・パススルー費用の処理／源泉徴収・消費税区分

### Step 3. 経理確認依頼シートの生成
以下の構成で生成する：

```
# 経理確認依頼：{契約名}（締結前）
## 1. 取引概要（3行・金額・期間）
## 2. 論点一覧
| # | 論点 | 該当条項（引用） | 想定される処理の選択肢 | 経理への質問 |
## 3. 締結スケジュールと確認希望期限
## 4. 注記：本シートは論点整理であり会計・税務判断は経理財務・税務専門家によるものとする
```

各論点は「契約文言→会計・税務上の分岐→選択肢」の順で書き、結論を断定しない。

### Step 4. CLMでの共有（要承認）
プレビュー提示→承認後：
1. `post_task_comment` で経理担当宛にシートを投稿（CLMタスクリンク付き）
2. 必要に応じ `change_document_property_values` で「経理確認中」等のプロパティ更新を提案

## 出力フォーマット
1. 経理確認依頼シート全文
2. 交渉担当者向けの1行サマリ：「締結前に潰しておくべき経理論点は n 件（最重要：◯◯）」
3. 次アクション提案：稟議に進むなら approval-brief を案内

# obligation-monitor：期限・更新・義務履行モニタリング（UC5）

## 前提
- `../_shared/clm_rules.md` と `../_shared/industry_presets.md` を必ず読み込むこと。
- デフォルトの期間ウィンドウは **今日から90日**。ユーザー指定があれば従う。
- 大量データはファイル保存→`jq`でフィルタしてから読み込む（コンテキスト保護）。
- CLM未接続時はサンプルデータで続行（明示）。

## 手順

### Step 1. 対象範囲の特定
1. `list_folder` でフォルダ一覧を提示し、監視対象範囲を選択してもらう（指定済みならスキップ）。
2. 監視条項の種類を業種プリセットで確認する：
   - trading：自動更新／価格改定／制裁・輸出管理条項
   - pharma：マイルストーン期日／独占期間／データ権利
   - staffing：抵触日／契約更新／個人情報保持期限

### Step 2. 期限データの横断取得
1. 対象文書ごとに `get_document_property_values` で期限系プロパティ（契約終了日・更新期限・自動更新有無など）を取得する。
2. プロパティに無い期日情報が必要な場合のみ、`download_document`＋条項抽出で補完する（全件ダウンロードはしない。件数が多い場合は期限接近順に上位から）。

### Step 3. リスク区分とソート
期限接近順に並べ、3区分でタグ付けする：
- 🔴 **不利な自動更新**：解約通知期限が迫っており、放置すると不利な条件で自動更新される
- 🟠 **義務履行期日**：マイルストーン・報告義務・支払等の履行期日
- 🔵 **更新機会**：条件改定・再交渉のチャンス

### Step 4. 特定条項の横断抽出（依頼時のみ）
「制裁条項を含む契約を全部出して」等の依頼では、対象文書を `download_document` し該当条項の有無・文言を抽出、契約名×該当文言の一覧表にする。

### Step 5. HTMLレポート生成
以下を含む単一HTMLを生成する：
1. サマリカード（🔴n件／🟠n件／🔵n件）
2. 期限タイムライン（今日〜90日）
3. 一覧表：期限日／契約名／相手方／区分／要アクション／CLMリンク（`https://clm.contracts-cloud.com/ws/documents/{documentId}` 形式）
4. 生成日時と対象フォルダを明記

### Step 6. アクション起票（要承認）
🔴案件について、担当者宛の `post_task_comment` またはタスク起票を提案する。承認後に実行。

## 出力フォーマット
1. チャット：サマリ3行（最重要の🔴案件を先頭に）
2. HTMLレポートファイル（実行環境の方法でユーザーに共有）
3. 定期実行の提案：「毎週月曜朝にこのレポートを自動生成できます」

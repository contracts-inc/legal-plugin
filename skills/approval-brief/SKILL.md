# approval-brief：稟議材料の自動生成（UC4）

## 前提
- `../_shared/clm_rules.md` と `../_shared/industry_presets.md` を必ず読み込むこと。
- 案件数値（売上見込・原価・与信枠など）が契約書・プロパティから取れない場合は、必要最小限だけヒアリングする。埋まらない項目は「要確認」として空欄のまま出す（数値を創作しない）。
- CLM未接続時はサンプル契約書で続行（明示）。

## 手順

### Step 1. 案件情報の収集
1. `download_document`＋`get_document_property_values` で対象契約と金額・期間等を取得。
2. `search_references` で関連契約（NDA・基本契約・付随契約）を検索し、案件の全体像を把握する。未紐付けの関連契約が見つかれば `relate_contracts` での紐付けを提案する（要承認）。
3. 同一会話内に clause-review／finance-impact の結果があれば取り込む（再分析しない）。

### Step 2. 業種別の稟議指標で整理
- trading：採算（ROIC・粗利）／与信（相手方・保全策）／為替下振れ感応度／損切り基準
- pharma：PoS込みNPV（前提を明示）／自社開発 vs 導入の代替案比較／マイルストーン支払total
- staffing：粗利・単価乖離／返戻リスク（過去実績があれば）／許認可リスク＝事業存続インパクト

### Step 3. 契約条項の「経営指標への翻訳」
稟議サマリの核。以下を契約条項から定量化・明文化する：
- **最悪シナリオ**：違約金・損害賠償上限・返戻・為替等の下振れが同時に起きた場合の最大損失額（根拠条項を引用）
- **撤退条件**：解除条項・中途解約の可否・違約金→「いつ・いくらで撤退できるか」
- **主要リスクTop3**：発生可能性×インパクトで選定、各リスクに緩和策1行

### Step 4. 稟議サマリの生成
1枚もの（A4相当）のMarkdownで生成。希望があればdocx化（docxスキル併用）：

```
# 稟議サマリ：{案件名}
| 項目 | 内容 |
| 案件概要 | （3行） |
| 採算 | （業種指標） |
| 最悪シナリオ | 最大損失 ◯◯円（根拠：第◯条） |
| 撤退条件 | （いつ・いくらで） |
| 主要リスクと緩和策 | Top3 |
| 法務・経理の確認状況 | （legal-handoff / finance-impact の結果があれば） |
| 添付 | CLM契約書リンク・関連契約リンク |
```

## 出力フォーマット
1. 稟議サマリ1枚（上記）
2. 「要確認」残項目のリスト（決裁前に埋めるべきもの）
3. 注記：数値の前提と出典（契約条項／ユーザー提供／プロパティ）を明示

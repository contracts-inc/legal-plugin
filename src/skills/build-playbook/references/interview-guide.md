## 回答スケールと進め方

質問は**番号で答えられる形**にします。個別の選択肢を作る必要がない場合は、以下の標準スケールを使います。

| スケール | 使う場面 | 選択肢 |
|---|---|---|
| **S1（要否）** | 「〜を要求するか」「〜を定めるか」 | 1 必須とする / 2 望ましい / 3 不要 / 4 保留 |
| **S2（可否）** | 「〜を認めるか」「〜を受諾するか」 | 1 認める / 2 条件付きで認める（条件を記入） / 3 認めない / 4 保留 |
| **S3（数値）** | 期間・金額・率を決める | 数値を単位付きで記入 / 保留 |
| **S4（個別）** | 上記で表せない場合 | その場で3〜5個の選択肢を作る（末尾に「保留」） |

- **どのスケールでも「保留」を用意する。** 選ばれた項目は `※要確認` として記録する。
- **判断材料は数値だけを添える**（例: 「過去12件中7件が12ヶ月です」）。文書名・条番号・事例の識別子は書かない。
- **「ケースバイケース」は場合分けの軸（金額 / 類型 / 立場 / 相手方属性）に分解する。** 分解できなければ `※要確認`。
- **未回答・保留は空欄にせず `※要確認` を明示する。** 推測で埋めない。
- **回答者の役割（法務部長など）と日付を根拠に記録する。** 個人名は残さない。
- **法令の要件は聞かない。** 「法令の要件を満たす前提でよいか」と、それを上回る自社の追加要件だけを確認する。条文は「e-Gov」法令検索コネクタで取得する。

## §0 情報源の確認（プレイブックの節には対応しない）

着手前に、何が使えるかを確認する（各系統の詳細は `evidence-sources.md`）。

- 社内規程（契約審査基準、決裁規程、購買規程、情報セキュリティ規程、過去のレビューメモ）の有無と提供可否
- **自社の契約書雛形**の有無、保管場所、自社作成か相手方提供か、立場別の版があるか、最終見直し時期
- 過去契約・交渉実績の取得経路（契約管理システム / 台帳 / ファイル / メール / 口頭）と件数
- インシデント・トラブル事例集、監査報告、クレーム管理台帳の有無（無い場合は対話で聴取）
- 係争中・調査中の案件の有無と、プレイブックへの反映可否
- 適用される業規制、下請法の適用可能性、個人情報の取扱いと越境移転の有無
- （改訂時）レビュー記録・版更新の変更理由の参照可否、前回改訂時期、年間レビュー件数、レビュー担当者数

## §1 基本方針

### §1.1 自社の立場と優先事項
- **取引形態の棚卸し**（契約類型 × 自社の立場 × 件数の多い順）。**これがスコープ決定と分割判断の入力になる**
- 自社雛形を使うか相手方雛形を使うことが多いか
- 契約審査の対象範囲（全件 / 金額基準以上 / 非定型のみ）と法務の体制・年間審査件数
- リスク許容度、判断に迷ったときにどちらへ倒すか、交渉スタンス
- 相手方の属性（大企業 / 中小 / 官公庁 / 海外 / 個人）や取引の継続性で方針が変わるか

### §1.2 エスカレーション基準
- 契約金額のしきい値（複数段階すべて）と各段階の承認者（**役割名**）
- 金額以外でエスカレーションする条件
- 「契約締結不可」を判断できる役割
- 決裁規程・職務権限規程に既定があるか（規程名と条番号）
- エスカレーションの記録先と所要時間（RED判定の粒度を決める材料になる）

## §2 条項別基準（§2.1〜§2.6）

各条項について**「自社基準 / 許容できない条件 / フォールバック」の3要素**を、判定可能な数値・条件で決める。立場で基準が変わる条項は立場別に分けて決める。

| 節 | 決めること |
|---|---|
| **§2.1 損害賠償の制限** | 上限の算定基礎と数値、許容できる下限、相互適用の要否、除外事由の範囲、除外事由に別枠上限を設けるか、特別損害・間接損害・逸失利益の免責、事故対応費用の扱い、請求期限 |
| **§2.2 補償** | 相互性、対象範囲、責任上限の適用、防御権・和解権の帰属、通知・協力の手続要件 |
| **§2.3 知的財産権** | バックグラウンドIPの扱い、成果物の帰属（立場別）、著作権法27条・28条の明記、著作者人格権の不行使、受託者に残すライセンス範囲、汎用ノウハウ・第三者素材の取扱い |
| **§2.4 データ保護** | 個人情報を扱う場合の必須条項、再委託の可否形式、漏洩事故の報告期限と許容範囲、終了時の返還・破棄、保存場所・期間、越境移転の要件、監査の方法と求める第三者認証 |
| **§2.5 契約期間・解除** | 当初期間、自動更新と更新拒絶の通知期限、中途解約権と予告期間、違約金、催告期間、無催告解除事由、反社条項の必須性、支配権変動・地位譲渡の扱い、存続条項の対象と期間、解除時の清算 |
| **§2.6 準拠法・紛争解決** | 準拠法、紛争解決手段、管轄裁判所、仲裁の条件（機関・地・言語）、弁護士費用の負担、契約書の言語と正文 |

## 見落としやすい規制フック

**適用の有無だけを確認し、条文の内容はe-Govで取得する。** 自動的には想起しにくく、抜けると法令違反に直結する項目を挙げる。

| 領域 | 確認するフック |
|---|---|
| 下請法 | 適用判定（資本金区分 × 取引類型）、支払期日、発注書面の記載事項、書類の保存、禁止行為への該当 |
| フリーランス法 | 特定受託事業者との取引か、取引条件の明示義務の履行方法 |
| 労働者派遣法・職業安定法 | 派遣可能期間と抵触日通知、指揮命令者の特定、派遣と請負の区分（偽装請負の回避） |
| 個人情報保護法 | 委託 / 共同利用 / 第三者提供のどの整理か、越境移転の根拠、漏洩時の本人通知・当局報告の責任分担 |
| 独占禁止法 | 再販売価格の拘束、競合品取扱制限、テリトリー制限、優越的地位の濫用に当たる要求 |
| 建設業法 | 一括下請の禁止、書面の記載事項、見積期間 |
| 輸出管理・経済制裁 | 該非判定の責任、denied party スクリーニング、再輸出の制限 |
| 業規制 | 金融の外部委託先管理、医療の情報安全管理ガイドライン、電気通信の通信の秘密、薬機法・医療広告 |
| 贈収賄防止 | 公務員が関与する取引か、外国公務員贈賄・FCPA / UKBA の適用可能性 |
| OSS・知財 | 使用を禁じるライセンス種別、SBOMの要求、第三者権利の非侵害保証と調査範囲 |

## §3 重大度分類 / §4 交渉の優先順位 / §5 修正案の方針 / §6 運用・改訂

| 節 | 決めること |
|---|---|
| **§3 重大度分類** | GREEN / YELLOW / RED の3分類でよいか（既存のリスク分類体系があるか）、各分類の対応アクション、YELLOWとREDを分ける判断軸、GREENとみなす軽微な差異の範囲、複数のYELLOWが重なった場合の扱い、REDでも締結を優先する例外とその承認者、聴取した事例のうちREDの具体例に反映するもの |
| **§4 交渉の優先順位** | Tier 1（締結できない項目）/ Tier 2 / Tier 3（譲歩材料）の割り当て、Tier 1のエスカレーションなし譲歩を禁止するか、スピードと条件のどちらを優先するか、相手方が修正を一切受け付けない場合の方針 |
| **§5 修正案の方針** | 修正案の粒度（提示できる文言まで作るか）、外部共有可能な理由と社内限りの理由を分けるか、フォーマットに追加する項目、標準文言の有無、提示方法、記録先、相手方が受諾しなかった記録を残すか |
| **§6 運用・改訂** | 承認者（役割名）、定期見直しの頻度、改訂トリガー、参照者の範囲（**フォールバックとTier配置は交渉上の機密である旨を伝える**）、版管理の方法、事業部門向け簡易版の要否 |

## 回答が得られない場合の扱い

| 状況 | 対応 |
|---|---|
| 「決まっていない」 | 実績レンジまたは一般的な水準を選択肢として提示する。選べなければ `※要確認` |
| 「ケースバイケース」 | 場合分けの軸を選択肢として提示し、条件に分解する。分解できなければ `※要確認` |
| 回答者に決定権がない | 決定権者（役割名）を確認し `※要確認（決定権者: 〇〇）` として残す |
| 既存の社内規程と矛盾する | どちらを採用するかを確認する。勝手に一方を採用しない |
| 法令上の強行規定に反する | 該当条文を示して指摘し、法令要件を下限として設定する |
| 質問の意図が伝わらない | 具体的な条項例・トラブル例を挙げて言い換える。専門用語を避ける |

# 一括フォームの書式

> **このファイルについて:** 確認事項をまとめて記入してもらうためのフォームの**書式**を定義します。設問そのものは列挙しません（出力仕様である `playbook-schema.md` の節構成と3要素を満たすために必要な設問を、その回の対象範囲に応じて組み立てます）。配布の条件は `interaction-format.md`「4. 一括フォーム」に従います。

---

## 冒頭に置く記入方法

```markdown
# ヒアリング記入フォーム（〇〇契約 / 委託者としての基準）

## 記入方法
- 各項目の `回答: [ ]` に、選択肢の番号を記入してください。
- 数値が必要な項目は、番号のあとに続けて記入してください（例: `[ 4 / 3,000万円 ]`）。
- 複数選択できる項目は、番号をカンマ区切りで記入してください（例: `[ 1, 3, 5 ]`）。
- わからない項目・決まっていない項目は **`保留`** と記入してください。空欄のままでも構いません。
- 担当が分かれる項目は、分かる範囲だけ記入して他の方に回していただいて構いません。
```

---

## 設問の書式

**1問 = 見出し（通し番号＋問い）＋選択肢1行＋記入欄** の3行に収めます。

```markdown
**12. 賠償上限の算定基礎をどれにしますか**
1 直近12ヶ月の対価（推奨: 実績で最多） / 2 直近6ヶ月の対価 / 3 契約総額 / 4 定額（金額を記入） / 5 上限を設けない / 6 保留
回答: [ ]

**13. これ未満は受諾しないという下限は何ヶ月ですか**（数値を記入）
回答: [ ]

**14. 上限の除外事由として許容するもの（複数選択可）**
1 故意・重過失 / 2 守秘義務違反 / 3 知財侵害 / 4 人身損害 / 5 データ漏洩 / 6 法令違反 / 7 除外を認めない / 8 保留
回答: [ ]
```

- **選択肢は `interaction-format.md`「1. 選択フォーム（基本形）」の標準スケール（S1〜S4）を使う。** 質問ごとに考える必要はない。
- **推奨・既定がある場合は括弧で短く添える**（根拠は「実績で最多」「法令の下限」程度）。
- **単一選択は選択肢6つ以内**（「保留」を含めて7つ以内）。**複数選択のチェックリストは上限の対象外**とし、見出しに「（複数選択可）」と明記する。
- **各設問に「保留」を置く。** 記入されなかった項目・「保留」の項目は `※要確認` として記録する。

## セクションの並び

プレイブックの節順（`playbook-schema.md` §2）に並べ、見出しで区切ります。

```
§1.1 自社の立場と優先事項 → §1.2 エスカレーション基準 → §2.1〜§2.6 →
§2.7以降 追加条項の要否 → §3 重大度分類 → §4 交渉の優先順位 →
§5 修正案の方針 → §6 運用・改訂
```

- **該当しない類型・規制のセクションは作らない。** §1.1 の棚卸し結果に該当するものだけを含める。
- 通し番号は先頭から連番にする。
- 追加条項（§2.7以降）は「追加する条項（複数選択可）」の1問にまとめ、選ばれた条項の詳細は後続の逐次確認で聞く。

---

## 立場が分かれる場合

**立場ごとに別のフォームを配布します**（1つのフォームに両方の立場を混ぜない）。

- 立場で変わるのは主に §2.1〜§2.6 と類型別の項目。§1・§3〜§6 は共通のため、**2枚目以降からは省く**。
- 2枚目の冒頭に「1枚目（〇〇としての基準）と同じでよい項目は『同じ』と記入してください」と添える。全項目を再記入させない。

---

## 回収後

1. 記入内容を**要約せずに**そのまま基準へ反映する（要約は出力量を増やすだけで確認の役に立たない）。
2. 未記入・「保留」は `※要確認` として記録する。
3. 矛盾・欠落がある項目、判断が重い項目（RED判定の境界、エスカレーション先、基準の緩和）は、選択フォームで個別に確認する。
4. 返却は `.md` / `.docx` / `.csv` / `.xlsx` のいずれでも受け取る。表形式で返された場合は `scripts/extract_review_feedback.py` で読める。

# プレイブックの骨格

> **このファイルについて:** プレイブックの最小の骨格と、1条項分の記入例です。節構成の定義は `playbook-schema.md`、記入済みの全体像は `review-contract/references/playbook.md`（サンプル）を参照してください。本ファイルは重複させないため骨格のみを持ちます。

---

## 冒頭（メタデータブロック）

節番号を持たないブロックとして、タイトル直後に置く。

```markdown
# 契約書レビュー プレイブック

| 項目 | 内容 |
|---|---|
| 版数 | 1.0 |
| 最終更新日時 | 2026/08/28 15:00 |
| 承認者 | 法務部長 |
| 承認日 | 2026/08/28 |
| 次回見直し予定 | 2027/08/28 |
| 対象範囲 | 業務委託（委託者）、SaaS利用（顧客）、NDA（双方） |
```

- 最終更新日時は**承認された改訂を確定したときだけ**更新する。
- 類型ごとに分割している場合は、そのファイルが扱う類型と立場を「対象範囲」に明記する。

## 節構成

```
1. 基本方針
   1.1 自社の立場と優先事項
   1.2 エスカレーション基準（表形式: 条件 / エスカレーション先）
2. 類型別・重要条項のチェックポイント
   2.1 損害賠償の制限 (Limitation of Liability)
   2.2 補償 / 損害賠償の範囲 (Indemnification)
   2.3 知的財産権 (Intellectual Property)
   2.4 データ保護とセキュリティ (Data Protection)
   2.5 契約期間と解除・反社条項 (Term and Termination)
   2.6 準拠法と紛争解決 (Governing Law and Dispute Resolution)
   2.7以降 業種・取引特性による追加条項
3. リスクの重大度分類（🟢 GREEN / 🟡 YELLOW / 🔴 RED。各: 定義・具体例・対応）
4. 交渉の優先順位（Tier 1 必須要件 / Tier 2 強く推奨 / Tier 3 あれば尚可）
5. 修正案（レッドライン）作成ガイドライン（基本原則＋修正案フォーマット）
6. 改訂履歴（表形式: 版 / 日付 / 変更概要 / 承認者）
```

見出しの文字列（英語併記を含む）は上記のとおりにする。§2.1〜2.6 の番号は変更しない。

---

## §2.x の記入例（この形を全条項で繰り返す）

```markdown
### 2.1 損害賠償の制限 (Limitation of Liability)

**自社基準:**
- 賠償上限: 直近12ヶ月間の委託料相当額（許容範囲: 6ヶ月〜24ヶ月）
- 上限は相互適用とする
- 除外事由: 故意・重過失、守秘義務違反、知財侵害
- 特別損害・間接損害・逸失利益は相互に免責

**許容できない条件:**
- 賠償上限なし（青天井）
- 上限が直近3ヶ月の委託料以下
- 自社のみに特別損害の免責がない非対称な構成

**フォールバック:**
- 上限を直近6ヶ月の委託料まで引き下げることは許容
- 除外事由の追加は、上限の引き上げとセットで交渉

> **根拠:** 契約審査基準 §4.2（社内規程） / ベンダー契約12件の締結実績（契約管理台帳10件・本文確認2件。6ヶ月:3件、12ヶ月:7件、24ヶ月:2件） / 2026年法務方針ヒアリング
```

- 3要素（自社基準 / 許容できない条件 / フォールバック）はすべての条項に置く。
- 立場で基準が変わる場合は、同じ節の中で立場別に書き分ける。
- 確定していない値は空欄にせず `※要確認` と書く。
- **法令の条文・数値は書かない。** 「法令の下限を満たすこと」と適用判定の条件のみを書く。
